### 1. 内测 + 扩展能力与流程 + onboarding

- **目标**：真外人在页面上把一个真课题从需求走到验收；过程中撞到的每个坑修根因，缺的能力抽出来，内置流程与能力包变多。onboarding 是它的第一个 sub-issue——内测第一步撞的就是「环境全无、不懂命令的人怎么上手」。
- **边界**：只改内仓；新能力照 `platform/docs/add-a-capability.md` / `add-a-skill.md` 接，流程照 `workflows/`；不动纲领（发现纲领有冲突回来提，不改）。
- **入口**：外层 README 文档地图 → 内仓 `CLAUDE.md` → `docs/start-a-workspace.md`、三份 add-a-* 手册；最近一张演练卡 `docs/cases/gua-codex-drill/`。
- **产出 / 验收**：每个课题一张案例卡（时间线、坑与修法、留着的债）；每个坑一条 issue 带根因；新能力过 `make check` 并出现在 `ai4sci show caps`；onboarding 的验收是「一个没装过任何东西的人照文档 30 分钟内跑到 `ai4sci serve` 起来」。
- **依赖**：Windows（学生的笔记本）、降成本（学生的账号）汇到这里。

### 2. Windows 适配

- **目标**：Windows 上装得起、跑得通研究流。
- **边界**：三个口子——本机进程控制（`backends/_procs.py`、`workspace/jobs.py`）、传输（`compute/ssh.py` 的 rsync）、`~/.config` 路径（`paths.py` `computes.py` `agents.py` `backends/codex.py`）；先定原生 + Git Bash 还是 WSL（倾向原生）。
- **入口**：`platform/framework/README.md` §1 §5；CI 加 windows-latest 作业先允许失败，把红的列成清单。
- **前提**：借到一台 Windows 机、开好 OpenSSH 服务端，从 mac ssh 过去做。

### 3. 调研成熟的科研 AI 能力

- **目标**：文献、假设、写作三个阶段现在没有步骤；调研大家在用、够成熟的 AI for science 能力（文献检索与综述、假设生成、论文写作与图表），提出接入形态。
- **边界**：只调研这三个空阶段，不扩到全链；只提案不写代码。
- **入口**：外层 `docs/architecture/README.md` P-18 P-20 P-22（阶段、主文件、步骤与 skill 两个 tag）、`workflow.md` §1；`research/README.md` 调研的写法。
- **产出 / 验收**：一篇 `research/landscape/2026-MMDD-<slug>/` 调研（公开区）+ 一份能力包提案：每个候选写清进哪个阶段、做成步骤还是 skill、输入输出文件、成熟度与许可证；工程师能照提案接。

### 4. 评测与流程 benchmark（并入 Q-4）

- **目标**：学生搭了自己的流程与能力包，要有通用指标说好不好、好多少。
- **起点**：盘上已有的机器信号——可信（数字回溯 PASS、账本对 git、σ 与门）、成本（`cost_usd`、轮数、墙钟，meta 与账本都记）、结果（相对基线的改进、与论文值的差距）；benchmark = 案例库固定的几道题 × 待评的流程 × 这三类数；噪声基线与组件消融是首选形态（`docs/architecture/open-questions.md` Q-4）。
- **边界**：仅限调研与方案，不写评测代码；李博士当理论顾问。
- **产出 / 验收**：一篇调研（业界怎么评 agent 工作流）+ 一份方案（指标定义、题库、怎么算、怎么防刷分）；会上认可后再立工程 issue。

### 5. 开源 agent 项目的适配器探索

- **目标**：借「能不能接进 `backends/` 端口」这个问题，读懂几个成熟开源单 / 多智能体项目。
- **边界**：探索与 spike，不要求合并进 main；接入门槛四样——非交互模式、结构化输出、会话续接、权限能收紧——缺一不接；实测六件事（隔离位、可写目录、命令放行、联网工具放行、事件流逐字、续接与成本上报）照 P-25。
- **入口**：`platform/backends/__init__.py`（两个 Protocol）、`backends/codex.py` 文件头的实测清单（一份适配器长什么样）、外层 `workflow.md` §5 执行层与协调层适配。
- **产出 / 验收**：每个项目一份 spike 记录（满足不满足四样门槛、六件事各怎么样、成本、结论接不接）；真要接由主人兜底。

### 6. 底座兜底与降成本

- **目标**：课堂上的学生不会都有满血订阅；先找最便宜的路。
- **先验证的两条**：Codex CLI 的自定义 model provider（OpenAI 兼容 base_url）能不能直接指到 DeepSeek 这类便宜 API（不用新适配器）；Gemini CLI 的免费额度够不够跑一轮研究流。
- **产品侧**：执行层用便宜模型（`agents.yaml` 已能分层选）、按能力给额度、减轮数；拿三轮演练的花费数据量。
- **要拍板的**：真要接「纯 API key 的轻量 agent」就是第三种适配器，与「不手搓 agent」有张力。
