## 1. 一句话

把科研链路交给一个"框架 + 底座 + 工具"的三箱结构：**框架只做决策与校验，底座 coding agent 是唯一执行者，工具是框架提供的确定性脚本。** 人只做判断。

## 2. 三个箱子

```
 ┌──────────────────────────────────────────────────────────────┐
 │ 框架  只做决策与校验，零模型调用                                 │
 │   编排   阶段顺序、产物契约校验、checkpoint 与续跑               │
 │   runner 跑实验、比分数、git 留或回滚、记账                     │
 │   验证   数字回溯、引用真伪、图源；不过就停                      │
 │   裁判   需要模型判断时派一个上下文隔离的新会话，只给产物         │
 │   人在环 阶段边界暂停，文件通道回传                              │
 └──────┬──────────────────────────────────────────────▲─────────┘
        │ 每个阶段一次调用：                              │ 产物文件
        │ 阶段指令 + 任务包 + 领域包 + 「去读磁盘上的状态」  │ 对契约 schema
        ▼                                                │
 ┌──────────────────────────────────────────────────────┴─────────┐
 │ 底座 coding agent  唯一执行者（Claude Code / Codex / …）         │
 │   文献、假设、实验设计、写代码、修 bug、分析、写论文               │
 │   每次新会话，上下文从磁盘来（runs/、账本、git log）               │
 └──────┬─────────────────────────────────────────────────────────┘
        │ 调用
        ▼
 ┌────────────────────────────────────────────────────────────────┐
 │ 工具  框架提供的确定性脚本，换底座能力不变                          │
 │   文献 API · harness 算分 · 引用校验 · 出图 · 领域求解器封装        │
 └────────────────────────────────────────────────────────────────┘
```

执行与决策的分界一句话：**产出文件的是执行，给底座；改变流程走向的是决策，给框架或人。**

## 4. 原则

编号 P-n，后面括号里是怎么用一条命令查。查不了的原则先当约定，代码落地时补成门禁。

- **P-1 底座是唯一执行者。** 框架不单独调 LLM 写文本。（`framework/` 下 grep 不到任何模型 API 名）
- **P-2 裁判上下文隔离。** accept / reject、验证、评审绝不由干活的那个会话做；确定性能判的用 runner 与零 LLM 判据，需要模型判断的派新会话，可指定不同模型，只给产物不给轨迹。（裁判调用点的输入参数里没有会话句柄）
- **P-3 状态在磁盘不在会话。** git 分支 tip 是当前最好，账本记全部尝试，阶段产物落文件；任何会话被杀，重启后从磁盘续。（kill 中途重启，续跑测试）
- **P-4 契约机器可校验。** 每个阶段的产物有 schema，对不上就 FAILED，不降级成模板。（契约测试）
- **P-5 框架不随任务改。** 任务包与领域包靠扫目录发现，没有注册表。（CI 里删掉全部任务包与领域包，框架测试照过）
- **P-6 评测由框架注入，模型改不了。** harness 只读、校验 hash、跑独立进程、只吃产物文件。（hash 门禁）
- **P-7 fail-closed。** 验证不过就停，不涂黑、不模板兜底、不静默降级；隔离等级降级必须显式失败。（红线：不许裸 `except`）
- **P-8 四条工程规矩。** 每个抽象合入必须带真实调用点；每个配置项必须有断言证明被读到；集成点必须有测试；不许裸 `except`。（review checklist，逐步进 lint）
- **P-9 上下文卫生。** 进底座会话的信息量每轮是常数：摘要与指标，不是整段日志；日志落盘不进 prompt。

## 5. 内仓目录约定（拟定，代码落地时以代码为准）

```
platform/
├── framework/          通用，不随任务改：编排、runner、契约、验证、裁判、人在环
├── backends/           底座适配器：claude_code.py  codex.py …  每个 60 到 80 行
├── tools/              确定性脚本：文献 API、引用校验、出图、harness 基类
├── domains/            领域包，一个领域一个目录（见 packs.md）
├── tasks/              任务包，一个任务一个目录（见 packs.md）
└── runs/               运行产物，不进 git
```
