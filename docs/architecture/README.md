# 架构总纲领

- 状态：协调层、执行层、流水线三层 **aligned**；学科适配、验证、评测三层 **draft**（未决项见 [open-questions.md](open-questions.md)）
- 最近变更：2026-09-19

这是不受任何具体任务约束的总纲领，**可以改**：改要双方认可，并在文末变更记录写清为什么。版本相关的内容不在这里，在 [`specs/`](../specs/)。依据在 [`research/`](../../research/)（行业调研与三个开源仓的代码级深读），这里只写结论，不复述证据。

## 1. 一句话

科研链路分四层：**协调层（人 + agent）做科研判断并拍板，框架是诚实执行的基底，执行层 coding agent 是唯一执行者，工具是确定性脚本。** 决策不在框架里；框架只做机械判定，并证明执行没有被改。

**产品是论文，不是内环**：一个研究问题进来，一篇每个数字、每条引用、每张图都能被机器核对的论文出去。文献、假设、设计、实验、分析、写作、验证七个能力都是这条链上的一环，实验内环只是其中唯一带循环的那一环。

## 2. 四层

```
 ┌──────────────────────────────────────────────────────────────────┐
 │ 协调层  人（PI）+ 协调 agent（科研助理）                             │
 │   人     定方向、拍板、随时叫停；角色不可替代                         │
 │   agent  持有目标与历史，读 issue / 记忆 / 磁盘，头脑风暴与大规模收集  │
 │          填契约、选下一个能力、解读结果、该问人时问人                  │
 │   载体   交互态 coding agent CLI + 项目 skill 包，像 Claude Code      │
 │          加本仓 CLAUDE.md；可换成 Codex、Copilot                      │
 └──────┬─────────────────────────────────────────────────▲───────────┘
        │ 调 ai4sci CLI，写 manifest 与契约                  │ 状态、账本、
        ▼                                                  │ 验证结论
 ┌──────────────────────────────────────────────────────────┴─────────┐
 │ 框架  诚实执行的基底，零模型调用，不做编排                              │
 │   能力   设计 / 实验内环 / 分析 / 验证 …，每个能力单独可调，跑完即退    │
 │   runner 跑实验、比分数、git 留或回滚、记账                           │
 │   契约   产物 schema 校验、checkpoint 与续跑、hash 门禁               │
 │   裁判   需要模型判断时派一个上下文隔离的新会话，只给产物               │
 └──────┬─────────────────────────────────────────────────▲───────────┘
        │ 每个能力一次调用：                                  │ 产物文件
        │ 指令 + 工作区里的产出 + 领域包 + 「去读磁盘上的状态」          │ 对契约 schema
        ▼                                                  │
 ┌──────────────────────────────────────────────────────────┴─────────┐
 │ 执行层  coding agent CLI 子进程，唯一执行者（Claude Code / Codex …）  │
 │   写代码、修 bug、文献、假设、分析、写论文；凡产出文件的活都在这         │
 │   每次新会话，无记忆，上下文从磁盘来（runs/、账本、git log）            │
 │   用执行层自己的 skill（跟领域包走），与协调层的 skill 隔离             │
 └──────┬─────────────────────────────────────────────────────────────┘
        │ 调用
        ▼
 ┌────────────────────────────────────────────────────────────────────┐
 │ 工具  确定性脚本，换执行层能力不变                                     │
 │   harness 算分 · 文献 API · 引用校验 · 出图 · 领域求解器封装           │
 └────────────────────────────────────────────────────────────────────┘
```

分界两句话：

- **科研判断归协调层，机械判定归框架。** 下一步试什么、这条路要不要放弃、结果有没有意思、何时停、何时找人，是协调层的事；指标比大小、schema 过不过、hash 对不对、预算超没超，是框架的事。
- **产出文件的是执行，给执行层；改变流程走向的是决策，给协调层。** 框架两头都不是，它只保证执行诚实。

契约的填写权在协调层：manifest 里的方向、预算、统计门、验收判据，是人和协调 agent 拍板后写进去的；框架只读，并证明它们在运行中没被改。

### 谁做什么

| | 协调层（人 + agent） | 框架 | 执行层 | 工具 |
|---|---|---|---|---|
| 定目标、写研究问题 | ✓ | | | |
| 填 manifest：方向、预算、统计门、验收 | ✓ 拍板 | 校验 schema | | |
| 选下一个跑哪个能力、要不要回退、何时停 | ✓ | 只报状态 | | |
| 跑一个能力、跑内环、记账、棘轮 | 发起 | ✓ | 产出文件 | harness 算分 |
| accept / reject、验证、裁判 | 读判决 | ✓ 确定性判 + 派隔离裁判 | | |
| 解读结果、决定是否找人 | ✓ | | | |
| 写代码、写分析、写论文、查文献 | | | ✓ | 脚本 |

协调层读裁判的判决，但不当自己派出去那份活的裁判：P-2 对协调层同样生效。

### 工作区：一份需求的家

端到端的起点是一个研究问题，不是一次实验。主人 2026-09-18 定：**一个工作区 = 一份需求**（P-15）。课题组一个项目可以有几份需求，就开几个工作区；颗粒度按需求切，不按项目切。2026-09-19 再定工作区里面怎么摆（P-19）：需求是根，七个阶段各一个目录，每次产出一个子目录，产出之间靠 `from` 引用——科研是频繁返修、多对多的，目录要装得下。

```
 工作区 workspaces/<id>/     一份需求的家（2026-09-19 按阶段重定，P-19）
 ├── requirement.md          需求：助理和人对话攒出来的；requirement.lock 是人的确认
 ├── materials/              原件，只增不改
 ├── flows/<name>.yaml       流程实例：从库里取来、按这份需求改过参数，几条都行
 ├── literature/ hypothesis/ design/ experiment/ analysis/ writing/ verification/
 │                           七个阶段各一个目录，每次产出一个子目录 <stage>/<n>/，meta.yaml 记读了谁
 └── .ai4sci/                平台记录：对话、作业、日志、工作树
```

库是全局的，实例是工作区的：能力代码、流程库（`workflows/`）、需求模板（`templates/`）、领域包在库里；需求、对话、流程实例、产出、作业全在工作区里。一个工作区一个文件夹，整个打包能交给同事。项目级（一篇论文、多份需求、文献与写作的产物）仍是上一节说的那一层，它的家等文献 / 写作能力落地再定（Q-9）；现在工作区之上没有目录。

### 可替换性

协调层与执行层都是集成进来的 coding agent，都不手搓，各自可换：今天协调层与执行层都用 Claude Code；换成 Codex 做协调、Claude Code 做执行，框架一行不改。具体用哪个 CLI 开工时定（Q-8）。两层的 skill 物理隔离：协调层的 skill 讲"怎么当科研助理、怎么驱动框架"，跟项目走；执行层的 skill 讲"怎么在这个领域做实验"，跟领域包走。

协调层的**形态**也可换。今天是人 + agent 在对话里按步调用能力；将来低代码平台上用户拖出来的一张图也是协调层：按边调同一批能力，图里还可以放"交给 agent 决定"的节点。框架为两种协调服务，一行不改（Q-13）。

## 4. 原则

编号 P-n，后面括号里是怎么用一条命令查。查不了的原则先当约定，代码落地时补成门禁。

- **P-1 执行层是唯一执行者。** 研究产物（代码、分析、论文、文献）只由执行层产出；框架不调 LLM 写文本。（`framework/` 下 grep 不到任何模型 API 名）
- **P-2 裁判上下文隔离。** accept / reject、验证、评审绝不由干活的那个会话做；确定性能判的用 runner 与零 LLM 判据，需要模型判断的派新会话，可指定不同模型，只给产物不给轨迹。协调层也不裁自己派出去的活。（裁判调用点的输入参数里没有会话句柄）
- **P-3 状态在磁盘不在会话。** git 分支 tip 是当前最好，账本记全部尝试，能力产物落文件，协调层的决定落 issue；任何会话被杀，重启后从磁盘续。（kill 中途重启，续跑测试）
- **P-4 契约机器可校验。** 每个能力的产物有 schema，对不上就 FAILED，不降级成模板。（契约测试）
- **P-5 框架不随任务改。** 工作区与领域包靠扫目录发现，没有注册表。（CI 里删掉全部工作区与领域包，框架测试照过）
- **P-6 评测由框架注入，模型改不了。** harness 只读、校验 hash、跑独立进程、只吃产物文件。（hash 门禁）
- **P-7 fail-closed。** 验证不过就停，不涂黑、不模板兜底、不静默降级；隔离等级降级必须显式失败。（红线：不许裸 `except`）
- **P-8 四条工程规矩。** 每个抽象合入必须带真实调用点；每个配置项必须有断言证明被读到；集成点必须有测试；不许裸 `except`。（review checklist，逐步进 lint）
- **P-9 上下文卫生，但不失忆。** 进执行层会话的是账本与实验笔记（有界：一轮几行，上限由轮数决定），不是 stdout 与整段日志；日志落盘不进 prompt。每轮新会话是为了上下文不膨胀，记忆放磁盘每轮读回来（P-3）。
- **P-10 决策不在框架里。** 框架没有"下一步"：每条 `ai4sci` 子命令只跑一个能力，跑完写状态退出，不连跑、不回退、不等人；串起来的是协调层。（CLI 里没有一条命令会连续起两个能力；`framework/` 里没有能力顺序表）
- **P-11 两层 agent 都是集成的、各自可换、skill 隔离。** 协调层与执行层都不手搓；执行层会话的 skill 搜索路径里没有协调层的 skill 目录，反之亦然。（适配器测试断言两条搜索路径不相交）
- **P-12 能力可自由装配。** 模块的粒度是能力，不是函数：内环是一个节点带参数，不拆成十个节点；每个能力有机器可读的描述符（属于七个研究阶段中的哪个阶段、给研究者看的人话标题、五栏说明、参数 schema、要不要执行层）；能力对外是一个 Python 函数加磁盘产物，CLI 只是薄壳，协调 agent、UI 后端、测试调同一个函数。描述符与接口从真实例里抽，不先画接口再填。（每个能力子包有描述符且 CLI 参数与之一致，`capabilities.discover()` 断言；2026-09-15 落地：`framework/contracts/capability.py`；2026-09-17 加阶段与人话字段。阶段是标签不是流程，目录不按阶段套，能力上不写「属于哪条流程」，那是反查。2026-09-17 补：**页面同理**——主页面右侧是当前 run 照的那条流程，一项一个模块，装什么流程长什么样，不写死流程；两块看板以可写目录划界：编辑台改库 `workflows/`，主页面改实例 `task/` `runs/`，[#58](https://github.com/zephyr4123/TJU-AI4Science/issues/58)。**2026-09-18 收窄**：「自由装配」的自由来自 P-18 的阶段任意组合与能力清单的丰富度，不来自检查器；"契约挂在产物上、任意子集都能单独成流程"那一套按路径对表的检查删了，[#93](https://github.com/zephyr4123/TJU-AI4Science/issues/93)）
- **P-13 文档即接口。** 产物是文件，不是 schema：一个文件只有一个生产者，格式由生产者定，谁要用就报名字、不问格式。这个系统里 agent 无处不在，读一句人话说明去发散，比读固定 schema 更好；schema 只在产物要给机器读时才补（那时生产者多吐一份 JSON，人读的从它渲染）。命名三规矩：**生产者就是命名空间**，产物放自己那次产出的目录 `<stage>/<n>/` 里，路径唯一；**名字是角色名词，版本在文件里**，叫 ledger、report，不带模型名、日期、版本号、第几轮，格式变了文件里记 `format_version`，含义变了换新名字、老名字不改义；**消费者只准报生产者原样声明过的名字**，不通配、不模板。产出目录就是命名空间：`<stage>/<n>/` 里的文件由产它的能力命名，不带能力名（P-19）。（2026-09-17 落地，[#54](https://github.com/zephyr4123/TJU-AI4Science/issues/54)。**2026-09-18 收窄**，[#93](https://github.com/zephyr4123/TJU-AI4Science/issues/93)：它管产物怎么命名、谁能写，**不管流程能不能拼**——按路径字符串对表让七个能力只能拼成一条线，而且是「有名字的耦合、没内容的契约」；`discover()` 的输出唯一 / 输入有出处两条断言、种子、桥、`check_flow` 全删。内容契约在描述符的「产出」栏里用工程语言说）
- **P-14 CLI 主导封装。** 协调 agent 面前只有 `ai4sci` 一个入口：它要做的每个动作都是一条直观的子命令，参数走 flag——不写路径、不在命令前挂环境变量、不接管道、不裸跑 python、不手搬文件。配置（模型、预算、超时、目录）归起服务的人和环境变量，不归命令。agent 需要做、却没有按钮的动作，是平台的缺口：立 issue 加按钮（一个能力子包、一张描述符，CLI 子命令、页面节点、流程检查自动跟上），不放行裸命令、不开 `exec` 逃生口。（机器判据：服务的 Bash 白名单只有 `Bash(ai4sci *)`；指南代码块里每条命令以 `ai4sci ` 开头、不含 `|` `;` `&`、不含 `.venv/bin`、不含 `X=y ai4sci`，`test_chat_guide` 守着。2026-09-17 落地，[#60](https://github.com/zephyr4123/TJU-AI4Science/issues/60)：白名单收口、venv bin 进 PATH、第 7 个能力 `cap init` 起任务包、指南去裸命令。2026-09-17 晚主人实测后补两条：**前期别设坎**——带 `.venv/bin/` 的老写法也放行，老会话会照自己以前几轮的写法来，指南只教裸写法；**给研究者看的话不用平台内部的词**——「按钮」「能力单元」不出现在指南、页面与 agent 的回话里，每条命令翻成「查了什么、跑了什么、写了什么」，[#69](https://github.com/zephyr4123/TJU-AI4Science/issues/69)）
- **P-15 工作区即边界。** 一个工作区 = 一份需求；库是全局的（能力、流程库 `workflows/`、领域包），实例是工作区的（需求、原件、流程实例 `flows/`、七个阶段的产出、对话、作业）。流程分两层：库 → 工作区里的实例（`ai4sci flow take` 取来、改参数、增删步骤）；能力只在实例下跑。命令不带工作区路径：CLI 从 cwd 往上找 `workspace.yaml`，agent 的工作目录就是工作区。（机器判据：`workspaces/<id>/` 之外没有产出、对话与作业；`framework/` 里读数据根的只有 `paths.py` 一处。2026-09-18 落地，[#70](https://github.com/zephyr4123/TJU-AI4Science/issues/70) [#72](https://github.com/zephyr4123/TJU-AI4Science/issues/72)）
- **P-16 造流程与用流程分权。** 主页面的助理只能用流程：取一条、按需求改参数、照着跑、跑偏了修；不造新流程、不造能力。编辑台另有一位流程助理，只管把能力拼成流程存进库，不跑实验、不动任何工作区。两位助理两份指南、两组可写目录、两个端点前缀，主页面的对话物理上到不了库；要新流程，研究助理说一句「去编辑台拼」。（机器判据：研究助理的指南里没有 `workflows/` 的写法、没有「拼一条自己的流程」；两组可写目录不相交；`test_chat_guide` 守着。2026-09-18 落地，[#70](https://github.com/zephyr4123/TJU-AI4Science/issues/70) [#73](https://github.com/zephyr4123/TJU-AI4Science/issues/73)）
- **P-17 素材上 CDN，图标内联。** 页面里的图片与视频只写自己 CDN 的 URL，仓库里不放二进制素材；图标全站一套（Phosphor），以内联 SVG 渲染。素材从来源站（motionsites、Pexels 这类）下到本机、处理好（裁成无缝循环、压尺寸、faststart）再推自己的桶——不直接引第三方的源：源站在境外，当 hero 背景加载不出来等于没有。来源、作者、许可记进内仓 `docs/DESIGN.md` 的素材清单。（机器判据：`git ls-files ui/` 里没有 png / jpg / mp4 这类二进制，`make ui-check` 守着；素材 URL 只在 `ui/web/src/assets.ts` 一处。2026-09-18 落地，[#75](https://github.com/zephyr4123/TJU-AI4Science/issues/75) [#76](https://github.com/zephyr4123/TJU-AI4Science/issues/76)）
- **P-18 三层：研究阶段、能力、实现；流程是按顺序经过几个阶段，断点是停下来等人确认。** 科研分七个阶段（文献、假设、设计、实验、分析、写作、验证），阶段不定先后，任意组合都成立；每个阶段里几个**能力**（一个阶段里的一件活，对协调 agent 就是一条 `ai4sci cap` 命令、一个 tool），细颗粒度，描述符五栏必填——职责、边界、输入、产出、终止条件——讲机制、带通用的专业术语；能力下面是**实现**（一段代码、一个 skill、领域包里的东西），一个能力可以有几种实现也可以暂时零实现，领域包只是打包单位、拆开各归各的能力。一条**流程**是经过几个阶段、按什么顺序、每个阶段挂哪些能力（可以不挂）、阶段之间哪儿插**断点**（停下来等人确认；「发布」「验收」是出厂的两个，机器守着记录，别的是助理的纪律）。阶段之间没有显式的输入输出接口、不做数据流校验：进入下一个阶段时助理自己看盘上有什么，缺了当场说；检查只查阶段名、能力归属、参数、断点位置。编排工作台的意义是立规矩（看得见、拦得住、下次照做），不是校验数据流。文档、指南、页面文案用直白的工程语言：命令就是 tool，「人按」就是人确认，不写「按钮」「键」「房间」这类比喻。（机器判据：`workflows.workflow_problems` 只有这三类问题；`Capability` 五栏空着断言炸；`framework/` 里没有 inputs / outputs 路径表。2026-09-18 落地，[#93](https://github.com/zephyr4123/TJU-AI4Science/issues/93)–[#99](https://github.com/zephyr4123/TJU-AI4Science/issues/99)）
- **P-19 工作区按阶段分目录，需求是根，产出多对多。** 一个工作区 = 一份需求：`requirement.md` 是助理和人对话攒出来的（形式开放，库里 `templates/` 按学科放模板，不定死大纲），`requirement.lock` 是人的确认——**唯一内置的门**，没确认任何阶段不开工；确认之后再改，页面显示 diff、人再确认成下一版。七个阶段各一个目录（英文 slug），每次产出一个子目录 `<stage>/<n>/`，id 就是路径；`meta.yaml` 记它读了谁（`from`，带 hash）、谁产的、在哪条流程第几项下产的、按哪版需求——多对多靠 `from`，不抄上游整包，进度沿 `from` 链算出来不另存。产出没被引用、没被签之前随便改，一旦被引用或被签就冻住。断点开放：几个、放哪由流程定，含义只有「这次产出要人签了下游才能读」，签字是产出目录里的 `signed.json`，发布 / 验收不再是特例。能力是纯函数：`--from` 点名输入，产出自己阶段下的一个新目录，不默认读「最新」，选输入是协调层（agent 看盘、或人）的事。**框架只认 `meta.yaml` `signed.json` `requirement.lock` 流程文件与能力描述符的形状**，产出目录里其它一切归产它的那个能力（实验族的 manifest schema、results、report 从 `contracts/` 搬进能力包），换学科就是换一族能力。平台自己的记录（对话、作业、日志、工作树）在 `.ai4sci/`，不是研究产物。（机器判据：`framework/` 里读产出内部文件名的代码只在 `capabilities/` 下；`contracts/` 里没有 metrics / budget 这类实验族字段；`workspaces/<id>/` 顶层只有需求、原件、流程、七个阶段目录与 `.ai4sci/`。2026-09-19 与主人从第一性原理重定，[#104](https://github.com/zephyr4123/TJU-AI4Science/issues/104)）
- **P-20 能力的接法：形状归框架、主文件归阶段、来源归 meta。** 接一个新能力要遵守的规矩分两层，分开就没有「泛化与明确的头尾不能兼得」这个悖论。**框架层**对所有能力一样，一共几条：读的只有需求（须已确认）、原件 `materials/`、`--from` 点名的产出；写的只有自己的 `<stage>/<n>/`；留一句结论（`meta.yaml` 的 `result`，助理与页面只看它，所以要说清留下了什么、下一步能拿它干什么）；要的文件不在就开工报错、说清缺哪个阶段的哪个文件。**能力层**各说各的：我要上游哪几个文件、我留哪几个文件，写在描述符「输入 / 产出」两栏，框架不校验、下游开工时自己核。「泛化」指一套**接法**适用所有能力，不是一套输入输出适用所有能力——像操作系统只规定程序从文件读、往文件写、退出码报成败，不管 grep 读的是文本。产出给谁用对所有能力也一样：人（页面列文件、人签）、助理（读 `result` 决定下一步 `--from` 谁）、下游能力（按文件名拿，拿不到报错）；上游不需要知道下游是谁。**熵的边界在阶段。** 文件名按阶段定、不按能力定：每个阶段钉一个**主文件**（设计 `scoring.yaml`、实验 `ledger.tsv` + `iters/iter_N/results.json`、分析 `analysis.md`、验证 `report.json`；文献、假设、写作三格待第一个进来的能力定名，之后锁死），进这个阶段的任何能力都必须留下它，下游只认阶段主文件、不认是哪个能力产的——换一个写作能力，读 `draft.md` 的审稿一行不改，这也是流程按阶段拼、能力可替换的前提。族文件（评分脚本、账本这类同族能力私下的约定）只在族包 `framework/<族>/` 里定，开新族是一次决策、不是顺手；能力另外留的文件是私有的，谁都不许依赖，下游要用就提成族文件。所以能力可以无限多，阶段主文件只有七种。**区分谁产的不靠文件名。** 文件名说「这是什么」，`meta.yaml` 说「谁产的、读了谁、按哪版需求」：`writing/1/draft.md` 与 `writing/2/draft.md` 同名，`by` 与 `from` 不同，页面的「来源 / 输入」、`show output`、hash 核对都读它；把能力名写进文件名就回到下游要认识每个能力。扫所有 `meta.yaml` 就是一张有向无环图（`from` 只指向已存在且冻结的产出，不成环）：需求版本是根、签字是节点状态、一条流程是一条路径，主页面的「一条流程一张表」是它沿一条流程的投影——图谱页是顺手的事，先立规矩。**skill 不是一格。** skill 是 agent 用的工具包（P-22），不开产出目录、不出现在流程里；写哪里由调用它的人定；要当一格就包成能力。领域包给能力的补充按族对文件（`domains/<包>/prompts/<族>.md`）。（机器判据：`capabilities.MAIN_FILES` 一个阶段一行，`discover()` 断言进这个阶段的能力「产出」栏写到了主文件；`meta.yaml` 有 `by` `from` `result`；产出目录里的文件名不含能力名。2026-09-19 与主人探讨后定，[#110](https://github.com/zephyr4123/TJU-AI4Science/issues/110)；主人未拍板的两条见 open-questions Q-14 Q-15）
- **P-21 页面词表：一个概念一个词，名词做标签，内部名不上屏，能力文案三层。** 页面、文档、指南共用一张词表（workflow §5 界面适配），一个概念只有一个叫法：workflow 叫「流程」，不叫「流」「库」「工作流」；量词用「个 / 次 / 项」，不用「颗」这类借来的量词。标签、列名、状态词、节点名一律两到四字名词；动词只出现在按钮上，两字；句子只进解释层（hover、空态、展开层），一句为限，工程语言不口语——「干什么 / 要带什么进来 / 可接着干 / 签了」这类聊天语气是 2026-09-19 主人看编辑台截图点名的病。**机器的名字不上屏。** 流程文件名、能力名、产出 id、参数名、CLI 参数在页面上一律翻译，翻译在源头做：后端随数据给中文（能力 `title` `brief`、参数 `label`、流程 `title`、阶段名、阶段主文件的中文名），前端不拼不猜；流程文件名照工作区 id 的规矩由标题生成，不显示、不让填；唯一例外是文件镜头，路径在那里是内容不是字段。**能力的文案分三层，对三种动作。** 名（名词，不超过八字；方法有公认名字的原样不硬翻——`auto-research` 叫 AutoResearch，不叫「自动实验」）直接显示；一行（`brief`，三十字内，说拿什么做出什么，不带路径与参数名）hover 显示；详情（五栏改名为 职责 / 边界 / 输入 / 产出 / 终止条件，工程语言陈述句，可写文件名——它们是工作区里真实存在的东西——不写 CLI 参数、框架内部机制与口语）点击跳转。一个阶段挂再多能力，版面上也只是名字的清单；协调层读的就是这份详情，不另写一份用户版。执行者的种类（模型还是程序、能不能续跑）不上屏：用户只关心做什么、要什么、留什么。编辑台两个镜头「流程 / 能力」：能力镜头按七个阶段陈列名字（空阶段写「暂无」），点了原地切详情页；流程镜头里节点上的小片、配置板里的名字点了跳同一页，配置板只剩勾选、名字、参数。（机器判据：描述符每个参数有 `label`、能力有 `brief` 且过长度与禁用词检查，`discover()` 断言；页面一条测试扫中文串、命中禁用词即失败，`font-mono` 只在文件镜头与代码块；给页面的 JSON 里凡 id / name / slug 必伴随中文字段。2026-09-19 与主人探讨后定，[#112](https://github.com/zephyr4123/TJU-AI4Science/issues/112)）
- **P-22 skill 系统：一个目录一个 skill，按开放规范写，框架自己注入，脚本自带依赖。** skill 是给 agent 用的工具包——一份说明（什么时候用、怎么用）、几个可执行脚本、几份参考资料——协调层与执行层都能用。它**不是流程里的一格**（P-18、P-20 不变），不开产出目录；写哪里由调用它的人定：研究助理调它写进 `materials/`，能力调它写进自己的 `<stage>/<n>/`。**格式照 agentskills.io 开放规范**（Anthropic 2025-12 开源，Claude Code、Codex、Cursor、Gemini CLI 等四十余家都认，不自造）：`<name>/SKILL.md` + 可选 `scripts/` `references/` `assets/`；frontmatter 只用规范的字段——`name`（等于目录名）、`description`（一句话，清单里只显示它）、`compatibility`（自由文本写运行时要求：Python 版本、系统包）、`metadata`（我们自己的键加 `ai4sci-` 前缀）——不用任何一家 agent 的专有字段，换适配器不失效；正文按 progressive disclosure 写，五百行以内，细节进 `references/`。**两处库**：平台通用的在 `skills/`（与 `workflows/` `templates/` `domains/` 平级，`AI4SCI_SKILLS_ROOT` 可指），领域的在 `domains/<包>/skills/`；名字全局唯一。**加载不靠任何 agent 的原生机制**（执行层的隔离参数本来就关了原生加载，协调层同样不开；P-11 --script` 出的锁文件与脚本同目录进仓；运行一律 `uv run --locked --offline`——uv 按脚本在全机缓存建隔离环境，所有工作区共享一份，锁漂移报错不静默，沙箱断网也照跑；`make skills` 承接时预热一次（唯一允许联网的一步）并探测 `compatibility` 写的系统包。skill 的 Python 版本由脚本自己定，与框架的 3.14、课题 `materials/env/` 的 venv 都解耦：三套环境互不 import，只用文件与 JSON 交接。脚本本身：非交互、有 `--help`、结果 JSON 到 stdout、诊断到 stderr、幂等、退出码说成败；写盘位置由调用方 `--out` 给。工作区级 venv 只在「某课题要求 skill 用别的版本」时才落（uv 的 `UV_PROJECT_ENVIRONMENT` 现成开关），那是那个工作区的事，不是缺省。**产物是文件**（P-13）：每个 skill 在 SKILL.md 写清留下哪几个文件、什么格式，换后端契约不变。第一个 skill 是 `pdf`：一篇论文 → `paper.md`（正文，公式 LaTeX、表格、图引用）+ `images/` + `structured.json`（分节、表、图、引用）；后端先 pymupdf4llm 打通接口，MinerU 4.0 basic 在真论文上实测过关就切主选，效果好的当缺省——两者都纯 CPU。（机器判据：`skills/` 与 `domains/*/skills/` 下每个目录有 SKILL.md、name 等于目录名、frontmatter 只含规范字段；每个 `scripts/*.py` 有 PEP 723 头与锁文件、`uv run --locked` 能过；两份 prompt 里的清单有测试；执行层会话跑得了 `ai4sci skill run`。2026-09-20 三路调研后与主人定，[#113](https://github.com/zephyr4123/TJU-AI4Science/issues/113)）

## 6. 文档关系

```
CLAUDE.md        红线（不许做什么）
research/        依据（调研得出什么）        ──▶ 纲领引用它
architecture/    纲领（系统长什么样）        ──▶ spec 引用它
specs/           版本 PRD（这版做到哪一步）  ──▶ issue 引用 R-n / A-n / Q-n
issue            过程（在做哪一件、做到哪）  ──▶ commit 引用 issue
adr/             仓库基础设施的决定，只追加
```

任何一层不复制上一层的内容，只链接。issue 里发现纲领有冲突，回来改纲领。

纲领改得慢，spec 改得快：**spec 是滚动的**，第 n 步的 spec 只驱动第 n+1 步的执行，做完一步回来改，不设 aligned 门槛。变化是常态。

协调层的上下文来源就是这几样：issue、纲领、spec、`runs/`；聊天记录不算。这既是我们做这个项目的方式，也是平台跑起来后协调 agent 的方式。

spec 与 milestone 用**产品版本**命名且带 `platform` 前缀（`specs/platform-0.2.0.md`、milestone `platform 0.2.0 · 初级版`）；外仓自己的版本线不进这两个名字。
