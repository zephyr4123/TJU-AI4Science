# 愿景与现状

## 目标

为课题组搭建一个科研全自动化平台：把文献调研、假设生成、实验规划与执行、结果分析、论文写作这条链路尽可能交给 AI 与自动化流水线，人聚焦在判断与决策上。

## 给谁用、凭什么（2026-09-16）

**给谁用：非工程师、非本专业的研究者。** 世界不是只由工程师组成的。用户是有一个科研问题、手里有一段能跑的代码和一个数、但不会也不该去学 harness、venv、校验和的人。每一个"要不要做、怎么做"的决定先问一句：一个化学系的博士生用得了吗。

**要解决什么。** 这些人今天已经在用 ChatGPT、Claude Code 调参、重复实验、整表格（学长访谈里"愿意交出去"的那一列，见 [vlm-hard-negatives](cases/vlm-hard-negatives/README.md)）。他们拿到的是一个数：不知道真不真，下周复现不出来，三个月后不知道当时为什么选了这条路。

**凭什么是这个平台，不是直接用 Claude Code。** 产品是两个词，缺一不可：

- **谁都能用。** 研究者跟 agent 聊天，agent 按按钮。命令行是给 agent 的按钮，不是给人的界面。人只在停点上拍板：签评分脚本、看基线决定开不开跑、看报告决定下一步。
- **数能拿去用。** 工程师拿到一个数还能自己核，研究者核不了，所以数必须天生可信：写代码的和打分的分开、评分脚本锁死、每轮落盘、新会话不带记忆。这是框架存在的唯一理由，也是它比"直接用 Claude Code"多出来的那一样东西。光降门槛，只是让不可信的结果产得更快。

**哪步复用现成的、哪步自己做，只有一条判据：模型能干的交给模型，模型不能自证的自己做。** 写代码、读文献、起草分析，交给 Claude Code / Codex 这些现成的会话。打分、锁脚本、统计门、记账、隔离环境，必须是零模型调用的死代码（P-1），因为让模型证明自己的数是对的等于没证明。这些死代码封成命令，agent 自由组装（P-12）。

**最终形态。** 研究者跟 agent 聊天：提想法、验假设、查文献、跑实验。agent 按按钮，按钮背后是可信的机器，人在停点上拍板。总目的：降低科研的门槛，且不降低结果的可信度。

**今天离它多远，如实记。** 入口是终端加七步手工，非工程师碰不了。收的形状很窄：几分钟跑完的代码加一个数，学长三个案例只有一个进得来。除了我们没人用过，第一个真任务是我们替学长接的。第一个真用户接入卡在哪，哪就是下一单元。

## 现阶段（0.x 骨架期，2026-09）

已定：

- 仓库拓扑：外层协作仓 + 内仓 `platform/` 生产 monorepo（见 [ADR-0001](adr/0001-nested-git-topology.md)）
- 版本与发布：CHANGELOG 驱动、tag 触发流水线、0.1.0 起步（见 [ADR-0002](adr/0002-versioning-and-release.md)）
- 托管：外仓与内仓都在 GitHub
- 架构（2026-09-10）：协调层（人 + agent）+ 框架 + 执行层 + 工具四层。科研判断归协调层，框架只做机械判定、不连跑不等人；执行层 coding agent 是唯一执行者，裁判上下文隔离；任务与领域是扫目录发现的插件；两层 agent 都集成不手搓、各自可换；能力可自由装配，子集也是流，低代码拖拽出的图是第二种协调层（2026-09-15，P-12）（见 [架构总纲领](architecture/README.md)）
- 协作方式：spec coding + issue driven，先对齐文档再干活，每个工作单元一条 issue
- 定位（2026-09-16，第一个真实输入到达后）：按**工业级开源项目**的标准完善——换一个人、换一个任务，不用问我们，照文档接进来就能跑；第一个真用户接入卡在哪，哪就是产品的洞（用户是谁、凭什么，见上一节）。真任务是检验流程的机会，不是绕过流程的理由：任务自带环境、领域知识有固定的家、接任务有固定流程、每一步机器能查

未定，等它自己长出来：

- 学科适配、验证、评测三层的具体做法（见 [未决项](architecture/open-questions.md)）
- ~~第一个真实工科任务与合作学院~~ 2026-09-16 已定：学院方向是交叉领域，第一个真任务是学长案例二（[案例库](cases/README.md)，[#40](https://github.com/zephyr4123/TJU-AI4Science/issues/40)）
- 是否有集群 / HPC 执行端，以及它是否需要单独成仓

当前版本 spec：[platform 0.2.0 初级版](specs/platform-0.2.0.md)，目标 2026-09-28。

## 里程碑

两条版本线各走各的（[ADR-0002](adr/0002-versioning-and-release.md)），milestone 与 spec 只用产品版本，且一律带 `platform` 前缀：

| 版本线 | 管什么 | 已发 | 下一个 |
|---|---|---|---|
| 外仓 | 项目之家：文档、调研、工具、CI | 0.3.0 | 攒够就发，不对应产品里程碑 |
| `platform` | 产品本身，路线图里的初级版、月度正式版 | 0.1.0 骨架 | 0.2.0 初级版 2026-09-28，之后每月 +0.1.0；内测打 `-rc.N` |

两条线都从 0.1.0 起步，0.x 不承诺兼容，正式发布才进 1.0.0。
