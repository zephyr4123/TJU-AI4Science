# 愿景

## 目标

为课题组搭建一个科研全自动化平台：把文献调研、假设生成、实验规划与执行、结果分析、论文写作这条链路尽可能交给 AI 与自动化流水线，人聚焦在判断与决策上。总目的：降低科研的门槛，且不降低结果的可信度。

## 给谁用

**非工程师、非本专业的研究者。** 世界不是只由工程师组成的。用户是有一个科研问题、手里有一段能跑的代码或一篇要复现的论文、但不会也不该去学 harness、venv、校验和的人。每一个「要不要做、怎么做」的决定先问一句：一个化学系的博士生用得了吗。

**要解决什么。** 这些人今天已经在用 ChatGPT、Claude Code 调参、重复实验、整表格（学长访谈里「愿意交出去」的那一列，见 [vlm-hard-negatives](cases/vlm-hard-negatives/README.md)）。他们拿到的是一个数：不知道真不真，下周复现不出来，三个月后不知道当时为什么选了这条路。

## 凭什么是这个平台，不是直接用 Claude Code

产品是两个词，缺一不可：

- **谁都能用。** 研究者跟助理说话，助理调用平台的能力；命令行是给 agent 的，不是给人的界面。人只在两处拍板：确认需求、在流程的断点上确认产出。
- **数能拿去用。** 工程师拿到一个数还能自己核，研究者核不了，所以数必须天生可信：写代码的和打分的分开、评分脚本锁死、每轮落盘、新会话不带记忆、每个数能回溯到产物文件。这是框架存在的唯一理由，也是它比「直接用 Claude Code」多出来的那一样东西。光降门槛，只是让不可信的结果产得更快。

**哪步复用现成的、哪步自己做，只有一条判据：模型能干的交给模型，模型不能自证的自己做。** 写代码、读文献、起草分析，交给 Claude Code / Codex 这些现成的会话（可换，纲领 P-11、P-25）。打分、锁脚本、统计门、记账、隔离环境、冻结与签字，必须是零模型调用的死代码（P-1），因为让模型证明自己的数是对的等于没证明。这些死代码封成命令，助理自由组装（P-12、P-18）。

**最终形态。** 研究者在页面上跟助理说话：提想法、复现论文、跑实验、看结果。助理按流程调用能力，能力背后是可信的机器，人在断点上拍板。产品是论文，不是实验内环（纲领 §1）。

## 定位

- 按**工业级开源项目**的标准完善：换一个人、换一个课题，不用问我们，照文档接进来就能跑；第一个真用户接入卡在哪，哪就是产品的洞。真任务是检验流程的机会，不是绕过流程的理由。
- 造的东西不是给我们自己用的：演练里每个坑都当成真用户会撞的，修根因、留机器判据；评估时问「一个不会 ssh 的研究者撞到这里会怎样」。
- 平台开源、去中心化：算力与 coding agent 都是使用者自己的（P-23、P-25），不依赖实验室的中心算力或谁的账号。

## 不做

- 多用户、鉴权：本机单人服务。
- 画布上的分叉与并行：流程是线性的一条链。
- token 级流式以外的实时协作。
- Slurm 这类调度系统：有第二个用例再写第二个算力适配器。
- 自研 agent：两层都集成现成的 coding agent CLI，自研的以后也只是第三个适配器。
- TUI：留位置没建。

## 今天离它多远

如实记（2026-09-23）：页面、流程、复现与改进两条流程、Codex 与 Claude Code 两家适配器、按人的算力与底座都有了；三轮真任务演练跑通过研究流与复现流全链（`docs/cases/`）。收的形状仍窄：几分钟到几小时跑完一次的代码加一个数；文献、假设、写作三个阶段还没有步骤；验证只有数字回溯与账本对账，引用真伪与图源未实现；模型评审未实现；除了我们还没有外人用过。系统长什么样见 [架构总纲领](architecture/README.md)，还没定的见 [未决项](architecture/open-questions.md)，仓库拓扑与发版见 [ADR](adr/README.md)。
