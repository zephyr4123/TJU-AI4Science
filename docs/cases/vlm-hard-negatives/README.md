- 应用领域：多模态机器学习
- 案例类型：过程访谈（[#1](https://github.com/zephyr4123/TJU-AI4Science/issues/1) 的「案例三 · 一段真实的研究过程」），形式是书面问卷，五问五答
- 状态：已入库，直接用于定阶段切分与人在环停点
- 喂给哪一层：协调层——人在哪几步拍板
- 原文：[interview.md](interview.md)
- 保密：这是学长本人主导的论文的研究判断过程，发表状态未告知。`docs/` 不进 Pages，不要搬进 `research/`

## 为什么这份最有用

三个案例里只有它是学长自己的工作，也只有它直接回答了我们架构里最缺外部证据的那个问题：人在哪儿拍板，哪些能交出去。

| 学长愿意交给助手 | 学长不交 |
|---|---|
| 文献整理 | 选题 |
| 重复实验 | 判断一个方向值不值得继续 |
| 参数测试 | 判断方法是否有足够创新性 |
| 实验表格整理 | 最终论文结论 |

他给的理由是左列「规则比较明确」。左列正好对应我们七个研究阶段里的文献、实验、分析；右列正好是协调层的活（P-10：科研判断归协调层，框架不连跑）。这是 P-10 的第一份来自研究者本人的证据，之前只有我们自己的推断。

导师的角色也值得记：判创新点够不够、效果不好时给修改建议、把关论文与图。这三件在我们的体系里同样落在协调层的人身上，不在任何能力里。

## 一条真实的失败轨迹

学长最初只做文本侧困难负样本。做完实验后靠两件事判定这条路不行：几个数据集上整体提升有限；与已有 hard-negative 方法相比创新性不足。于是转向视觉侧扰动加新损失函数，最终消融实验显示完整组合最好。

这条轨迹对我们有两个用处：

1. **验证层的边界是对的。** 否掉一个方向靠的是消融实验的数字加「创新性够不够」的判断，前者机器能验，后者不能。我们的验证能力只查数字有没有出处（R-6），不查结论对不对。真实研究里「对不对」也不是靠数字定的，所以这个边界不是我们偷懒，是分工。
2. **失败要留痕。** 「只做文本侧」是被数据否掉的，否掉它的那几个数字如果没记下来，三个月后没人知道为什么不走那条路。run 级的账本与笔记已有；跨实验的「哪条路为什么不走」落在项目层（一个项目一位助理，助理的本子与 `show project`，Q-9 已定），这条访谈是它的一个真实样本。

## 提纲覆盖与可追问的点

#1 给了五条提纲，五条都答了。因为是书面问卷不是电话，没有追问。以后见面可以追这几处：

- 第 2 条「先复现已有方法，确认实验结果和整个训练流程」：复现花了多久、卡在哪，这是复现型任务的成本参照。
- 第 3 条导师「对论文和图片质量进行把关」：把关的具体判据是什么，这是写作能力（Q-12）的验收条件。
- 第 4 条的消融实验：具体是哪几个数字让他下的决心、量级多少，这是「好多少才算真的好」的真实样本。
