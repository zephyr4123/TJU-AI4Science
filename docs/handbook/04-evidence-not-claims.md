# 04 未取证不下结论

## 场景

agent 说「已修复」「测试通过」「这个函数没人用」「删掉也没关系」。你要不要信。你自己说「应该是这个原因」，要不要现在就改。

## 做法

1. **什么算证据**：命令与它的输出、数字、`文件:行`、commit 哈希、截图。「已验证」「应该没问题」「我检查过了」不是证据。
2. **agent 报的 finding 是待验证输出。** 它读代码读得快，但会把猜测写成事实。逐条核：点开 `文件:行` 看是不是那么回事，跑它说跑过的命令。核实一条采信一条，不整批采信。
3. **提了假设就立刻验。** 「可能是 A 导致的」——下一步就是验 A 的动作，验不了写「未验证」。不许拿假设当结论往下推。
4. **先查再说话**：查代码、查 git log、查日志、查 issue。在内仓下「某功能不存在」之前先看 `./repos status` 有没有 prod 分支漂移告警，别在过时的本地副本上下结论。
5. **修坑修根因。** 症状消失不等于修好；问一句「不会 ssh 的研究者撞到这里会怎样」，答案通常指向根因。
6. **报告如实。** 失败就说失败、跳过就说跳过，附输出。一个粉饰过的「完成」比一个诚实的「卡在这」贵得多。

## 反例

- 「测试都过了」——哪个命令？多少条？退出码？跑的是改后的代码吗？
- 「这个目录没人用，删掉测试照过」——见下面第二条，说这话时目录被 `assert` 守着。
- 「大概是缓存问题」然后清缓存，问题消失又回来，因为根本不是缓存。
- 把 agent 的审计报告整份当结论，直接照着改十处，其中两处是它看错的。

## 本仓真实例子

- 一句错话被抓回来：[#140](https://github.com/zephyr4123/TJU-AI4Science/issues/140) 整理内仓文档时，草稿里写了「删掉 `domains/` 测试照过」。核对时发现内仓 `framework/paths.py` 的 `_existing` 会 `assert` 那个目录存在，删了必炸。`tests/README.md` 与 `docs/add-a-domain.md` 改回正确的说法。没有这一步核对，文档就教人做一件会炸的事。
- 读者的报告逐条核：一次全量文档盘点派了多个读者（见 [06](06-survey-before-acting.md)），回来一份几十条的「文档与代码不一致」清单。每条先点开它引的 `文件:行` 看真假，核实的才进 #140 修；有几条是读者把注释当成了行为。
- 四个坑修根因：[#137](https://github.com/zephyr4123/TJU-AI4Science/issues/137) 演练里 σ 算错、种子不对、探测缺解释器路径、页面四处不对。每个坑先找到出错的那一行（案例卡 [`docs/cases/gua-codex-drill/`](../cases/gua-codex-drill/README.md)「四个坑与修法」），再改：σ 改由框架从 `baseline/repeats/` 算，执行层不再自己写 `sigma.json`；复现的种子照论文，不用平台的 42–46。
- CI 红的根因：[#144](https://github.com/zephyr4123/TJU-AI4Science/issues/144)。看到红先 `gh run view --log-failed`，日志里是 `No module named pip`，再 `uv venv` 一个没 pip 的环境本地复现，修完在同一个环境上验证能写出 `requirements.lock`。
