1 · 复现的是什么：一篇交叉学科的论文

《Gradient–Update Mismatch: Rethinking Conflict-Free Training of Physics-Informed Neural Networks》，国防科技大学，2026 年 9 月 1 日挂出，代码 JingXiao10/GUA（MIT）。

它站在两个学科的交界上。计算物理那一侧是偏微分方程求解：Burgers、Schrödinger、Kovasznay、Heat、Beltrami、Poisson 六个经典方程，用物理信息神经网络（PINN）代替传统数值格式去逼近解，误差按相对 L2 范数对解析解或参考解算。机器学习那一侧是多目标优化：PINN 的损失由方程残差、边界条件、初始条件几项拼成，几项的梯度会互相打架；已有的「梯度手术」方法（PCGrad、ConFIG 等）在优化器之前把方向修成不冲突的，论文指出 Adam 这类优化器会把修好的方向再变回冲突的——它叫这个现象 Gradient–Update Mismatch——并提出 GUA：在优化器之后再把更新方向投影回不冲突的锥里。

平台这次接入的是它最小的一组：附录表 8，Burgers 方程、2-loss 拆分的两行——ConFIG（基线）与 ConFIG+GUA——论文报的是五个种子的均值 ± 标准差。选这一组是助理自己定的：Burgers 只训 3 万轮（其余五个方程 10 万轮）、数据随仓库附带不用另外下、ConFIG 是论文通篇的主基线。这两行对上，「加 GUA 有效」这个核心主张就算重跑成立。

接入的东西具体是什么

3 · 整条链路是怎么走的

平台里的复现是一条独立的流程 reproduce：文献 → 设计 → 人签 → 分析 → 验证 → 人验收。每一格由一颗能力（一条 ai4sci 命令）完成，格与格之间只靠文件名接。下面是这次真实发生的每一步，命令是助理自己敲的。

研究者 · 12:18

「我有一篇论文 https://arxiv.org/abs/2609.01558 你帮我复现一下」

助理 · 需求

看模板库发现有「论文复现」这一份；用 pdf 工具解析论文；在正文里 grep 表格与训练设置；顺着摘要里的链接读仓库 README；写需求初稿，问四件事：为什么复现、哪几行、复现到第几级、怎么算对上——外加有没有能跑 GPU 的机器。

ai4sci show templates
ai4sci show template reproduce
ai4sci skill run pdf --input https://arxiv.org/pdf/2609.01558 --out materials/paper/
WebFetch https://github.com/JingXiao10/GUA
研究者 · 12:25

「老师让我复现的，想看看这个方法靠不靠谱。级别和对上的标准都听你的。机器：之前那台 AutoDL 开不了机了，我克隆了一台新的，登录是 ssh -p … root@…，密钥还是原来那个，卡是 4090。时间就今天下午吧，钱别超过一百块」

助理 · 算力与环境

一句命令把新机器接进按人的算力清单（同名覆盖旧的），探测到 4090 / 24 GB / 磁盘；租来的机器不隔离新建、直接登记镜像自带的 conda 环境（126 个包冻成清单当出处）；把版本差写进需求。研究者在页面上确认需求 v1。

ai4sci compute add autodl --ssh root@<host>:<port> --key ~/.ssh/id_rsa --root /root/autodl-tmp/ai4sci
ai4sci env use --compute autodl /root/miniconda3/bin/python
助理 · 文献格

取 reproduce 流程到工作区；用 download 工具拉官方仓库（收据记下 commit、文件数、许可证）；手写文献格的主文件 sources.md：论文值、训练设置、代码版本、数据在哪、我们的环境与论文的差异、还缺什么。

ai4sci flow take reproduce
ai4sci skill run download git https://github.com/JingXiao10/GUA --out materials/GUA
ai4sci output new literature --title 材料来源
助理 · 设计格「原码复现基线」

框架把仓库搬进 code/、记下出处；执行层（另一个 agent，只能读和写、不能跑）写三个文件：起上游代码的 launcher.sh、把它的输出算成论文那两个数的 evaluate.py、目标值 = 论文值的 scoring.yaml；框架封住评分脚本、跑 lint 与契约校验，然后在 4090 上起 make_run0.sh：种子 0 一次 + 种子 1–4 重复 + σ。

ai4sci cap reproduction --from literature/1 --code GUA --compute autodl --detach

这一步撞了两次：执行层读完 79 个文件后用完了 30 轮额度、还没来得及自述；补上额度后草稿过了校验、连上 4090，import scipy 炸了——镜像环境里没有仓库要的九个包。助理看日志各自诊断了原因（种子写成 42–46 应为 0–4；平台没有「往现成环境里补包」这一步），见第 4 节。

4 · 算力与能力：这个案例逼出了什么

算力是按人接的：研究者手里只有 AutoDL 租来的一台 4090 和一行 ssh，平台只认密钥、不收密码，助理一句命令接上；远端只跑评分脚本，写代码的执行层留在本机。租来的机器直接用镜像自带的环境，不整套隔离新建——上一轮演练在同一家平台装 CUDA 版 torch 两个多小时没装完，这条规矩就是那时定的。

为了跑通这条复现流，平台在这两天里新搭或补上的东西：

能力做什么这次用在哪
流程 reproduce文献 → 原码复现基线 → 人签 → 复现性分析 → 数字核对 → 验收；与「改进」那条流程并列，复现不再被塞进改进的流程里去凑数助理看库里有两条流程，按需求选了它
需求模板「论文复现」哪篇、哪几个数、复现到第几级、对上的标准、算力与预算助理据此问了四件事，写完研究者确认
文献格主文件 sources.md材料来源：找到了什么、选了哪个、为什么、每样的链接 / commit / 许可证；框架只认文件名，不定 schema助理手写，下游两颗能力都读它
skill downloadgit / 文件 / Hugging Face 三个子命令，落到工作区、留收据；两层 agent 的命令只有 ai4sci，clone 一个仓库得经它拉官方代码到指定 commit
能力「原码复现基线」别人的代码进 code/，执行层只写壳，框架跑一次、论文值与我们的值并排、改动写进 upstream.diff；不判「对没对上」设计格
能力「复现性分析」读设计那包写六节分析；数字来源写成 design/1/scoring | baseline | repeat_<seed> | sigma，验证阶段回溯分析格，四版
env add往机器上现成的环境里补几个包，重新登记清单；接着跑不重写壳镜像缺 scipy / torchjd 那一步
执行层会话额度按能力给读懂别人整个仓库再写壳比从零写多得多；复现给 80 轮，提示里写清「读文件用 Read / Grep，Bash 只放行 ai4sci skill」第一次撞 30 轮上限之后
分析的 --feedback重写仍是新开一份，但上一版的问题进提示，执行层不盲改第四版一次过
对话锁记 pid、指南更新提醒人打断留下的死锁自己收；平台中途加了命令，下一轮话前提醒助理重看 --help补包那一步助理照上一轮记忆答「做不了」，之后才重翻
上一轮留下的：ssh 算力适配器、env use、job stop接机器、用现成环境、停作业接新 4090、登记环境

每个坑都当真用户会撞的修根因，不当一次性成本——不会 ssh 的研究者撞到「你去机器上 pip install 一下」就死在那里了。

5 · 平台涌现出了什么

下面这些没有一条是提示词里写好的具体做法，也没有一条是维护者喂的答案。指南只给了结构：该搜什么、问什么、拉材料用什么、每一格用哪颗能力、走到断点要停。选什么、怎么判、错了怎么办，是助理自己的。

找对了材料

从摘要里的链接直接读到官方仓库；从解析出的 structured.json 里抄表 8 的数，不凭记忆；拉到 commit、记下许可证与文件数。事后与维护者预筛的答案卷逐项对得上。

把大题切成能跑的小题

论文有 6 个方程 × 6 种方法 × 2 种拆分 × 5 种子，它挑了训练最短、数据现成、又是主基线的那两行，并说清「这两行对上核心主张就成立」。

自己定了统计口径

提出「五个种子均值落在论文 ±2σ 内，且方向对」当标准，同时留了「时间不够减到三个种子」的退路——它知道单种子会抖。

看日志诊断，而不是猜

执行层第一次没跑完，它读会话日志，说清是额度用完、还发现草稿种子写成 42–46 应为论文的 0–4；import scipy 炸了，它判断出是平台缺「补包」这一步，不是代码错。

自己起核对、自己通读

没人要求它跑数字核对，它跑了；核对通过后又逐句读，抓出机器核不出的文字错——编了个论文里没有的方程名。

给自己立验收线，不无限重写

第三版没过时它写下三条验收标准（数字回溯、文字事实、按需求口径明确判定），并说「再不过就把对的部分指给你，不再重写」。

把新命令接进正在跑的活

平台中途加了 env add 与 --feedback，它在被追问时重翻 --help 发现、当轮用上，接着上一次的草稿跑，没有推倒重来。

说人话、管闲事

全程没让研究者碰命令行；结尾给老师的一句话结论、交付清单、下一步建议，还提醒去关按小时计费的机器。

研究者说过的全部八句话在第 3 节里，没有一句超过两行。

7 · 保留意见

  • 这篇是预筛过的「好材料」。选它之前维护者派读者核实过：数据在仓库里、一条命令、MIT、单卡半小时。同批被筛掉的三篇——数据链接死、README 命令跑不起来、发布的权重与测试集重叠——才是复现里更常见的坑，还没考助理「发现材料有问题时该怎么说」。
  • 执行层写分析会编文字事实。数字核得住、文字核不住，靠助理通读兜底；四版才过。
  • 「对上」是人判的。平台只把两列数与全部差异摆清楚；前期不把机器校验卡太死，是有意的。
  • 一级复现的意思是「结果可重跑」，不是「论文写清楚了」：换实现、只照论文重写这两级没做。
