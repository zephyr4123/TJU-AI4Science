AAAI4S（后端包名 `ai4sci`）：天津大学课题组的科研全自动化平台。研究者在页面上跟助理说清课题、确认需求，助理照流程调用平台能力做文献、设计、实验、分析、验证，人只在断点上签字。

- **用户是非工程师、非本专业的研究者**（化学系博士生那种）。每个「要不要做」先问：不会 ssh、不懂 venv 的人用得了吗。
- **两个词缺一不可：谁都能用 + 数能拿去用。** 后者是框架存在的唯一理由：写代码的和打分的分开、评分脚本锁死、每轮落盘、新会话不带记忆、每个数能回溯到产物文件。
- **复用与自研的唯一判据**：模型能干的交给现成 coding agent（Claude Code / Codex，可换）；模型不能自证的（打分、锁脚本、统计门、记账、冻结与签字）必须是零模型调用的死代码。
- **产品是论文，不是实验内环**：七个阶段（文献、假设、设计、实验、分析、写作、验证），内环只是唯一带循环的一环。
- **开源、去中心化**：算力与 coding agent 都是使用者自己的；不要第三方 key 也能用（DeepSeek 十块钱跑通端到端是目标场景）。
- **不做**：多用户与鉴权、画布上的分叉并行、Slurm、自研 agent、TUI。

**Why:** 这是 `docs/vision.md` 与纲领 §1 的核心，几乎每个设计争议最后都回到「研究者核不了数，所以数必须天生可信」。
**How to apply:** 评估新功能、新依赖、新交互时先过这两问；想加「模型自评」「静默兜底」「要 key 才能用」的东西基本都违背主张。细节在 `docs/vision.md`、`docs/architecture/README.md`。相关：[[architecture-model]]
