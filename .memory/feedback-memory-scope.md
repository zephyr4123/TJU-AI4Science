记忆只收**有泛化性、能推动项目的上下文**：当前进展与下一步、技术栈、架构心智模型、未决的决策与债、踩过的坑里能复用的教训。不记流水账（某次改了哪个文件、某个 bug 怎么修的、git log 能查到的事）。

**不写团队分工，不出现任何人的名字**（2026-10-12 主人定）：早先的分工已经不适用，新的还没定，写了就是过期信息；所以不记谁负责什么、谁是什么角色，也不写姓名与账号。需要确认的事统一写「问主人」，与 `AGENTS.md` 的用词一致。分工以后定了，也要主人说记才记。

三者各放什么（2026-10-11 主人定）：
- `AGENTS.md`：红线、协作纪律、写代码与验收的标准、拓扑这类**不大会变**的东西；`CLAUDE.md` 只有一行 `@AGENTS.md`
- `.memory/`：**会变**的项目上下文，随 git 走、两个引擎共用
- 仓内文档（纲领、spec、ADR、案例卡）：细节的唯一出处。记忆写压缩后的判断加一句「细节在 X」，不抄正文

**Why:** 记忆每次会话都进上下文，流水账稀释信号；仓内文档已经是事实的家，抄一份就多一份会过期的副本。`.memory/` 随公开仓走，人名与分工既容易过期、也不该公开挂着。
**How to apply:** 写记忆前先问「三个月后新会话靠它能少走弯路吗」；写进度类记忆带绝对日期；发现记忆与代码或文档不一致，先核实再改记忆，不照记忆下结论。相关：[[project-status]]
